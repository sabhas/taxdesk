# Implementation status

**Current focus:** Sprint 1 implementation is complete. TD-001 to TD-005 are done, and TD-006 now provides the CI gates, staging delivery workflow, pull-request secret isolation, database/recovery posture checks, and operator alerting. Staging is deployed, migrated, green on `ci:db-posture` after its admin role was replaced with a least-privilege non-owner role, and serves a 15/15 staging smoke check; that check caught and the fix closed an environment-reporting defect in `/api/v1/app-info`. The staging posture evidence record, the first CI-driven staging deploy, and the branch-protection demonstration remain to be captured in Sprint Review.

**Epic 2:** client management (TD-201–TD-206) is implemented and passes every local gate, including the PostgreSQL migration and repository suites. It awaits the two client identifier secrets and migration `0005` in staging, a staging demonstration, and Sprint Review before the epic is marked done. It awaits migration `0011` in staging, a staging demonstration, a real-browser accessibility pass, and Sprint Review. No new secrets are required. TD-511 (combined group invoices, Epic 5) is implemented and verified locally; see Epic 5.

**Epic 3:** tax-case workflow (TD-301–TD-310) is implemented and passes every local gate, including the PostgreSQL migration and repository suites (database triggers and true concurrent races). It awaits migration `0006` in staging, a staging demonstration, and Sprint Review before the epic is marked done. No new secrets are required.

**Epic 4:** document storage (TD-401–TD-410) is implemented and passes every local gate, including the PostgreSQL migration and repository suites and a `/verify-epic` re-audit. It awaits a staging Microsoft app registration, `STORAGE_TOKEN_ENCRYPTION_KEY`, `ONEDRIVE_CLIENT_ID`, migration `0007`, a staging demonstration against a real OneDrive account, and Sprint Review before the epic is marked done.

**UI foundation (cross-cutting, not a backlog story):** the web app now uses shadcn/ui on Base UI with Tailwind CSS and the "ledger" design tokens ([ADR 0003](../adr/0003-ui-foundation.md), [design system](../technical/design-system.md)). The app shell and all existing Epic 1 screens were migrated with unchanged behavior; the production build was checked against the real content security policy with no violations. It is tracked as TD-007 in the Epic 0 PRD and still needs a staging visual check and Sprint Review acceptance.

**Epic 5:** billing and payments (TD-501–TD-510) is implemented and passes every local gate except `ci:secrets`, which flags two synthetic test values in the Epic 4 file `credential-vault.test.ts` (unchanged by Epic 5). PostgreSQL suites cover concurrent finalization, duplicate payments, over-payment and over-reversal races, and the database guards. It awaits migration `0008` in staging, a staging demonstration, and Sprint Review before the epic is marked done. No new secrets are required. TD-511 (combined group invoices, added 2026-11-21) is implemented and verified locally (`/verify-story`, 2026-11-22): migration `0012`, combined drafts from a group head, per-line client and case, group recheck and client snapshot at finalization, grouped PDF, and the duplicate-billing warning. It passes the local unit, route, role-matrix, web/axe, and PostgreSQL suites (including finalization racing a group change). It awaits migration `0012` in staging, a staging demonstration, a real-browser accessibility pass, and Sprint Review. No new secrets are required.

**Epic 6:** dashboard and operations (TD-601–TD-605) is implemented and passes every local gate, including the PostgreSQL migration and repository suites (report predicates against the reference, billing aggregates against invoice detail, audit search). It awaits migration `0009` in staging, a staging demonstration including the real-browser accessibility pass for TD-605, and Sprint Review before the epic is marked done. No new secrets are required.

**TD-806 (in-app staff help, added to Epic 8 on 2026-11-18):** implemented locally. The web build publishes the staff guides from `docs/training/` at `/help/`. The Pages Function serves them only after the API confirms the session, and each screen's Help link opens the matching guide. Unit, Function, and app tests pass, and the gate was exercised in local `wrangler pages dev` against a stub session API. It awaits a staging demonstration (signed-out redirect, unpublished pages return no guide content, Help link targets), a real-browser accessibility pass, and Sprint Review. No new secrets or migrations are required.

**Epic 7:** migration, security, and recovery is implemented. TD-701–TD-705 (versioned CSV templates, dry run, idempotent chunked commit, review/correction, import security) pass every local gate, including the PostgreSQL import suite. TD-706–TD-710 tooling and runbooks are in place: synthetic rehearsal data, migration reconciliation, an encrypted independent export workflow with manifest verification, restore verification, the security review (0 critical or high open after upgrading zod 4, drizzle-orm 0.45, hono, vite 6, and vitest 4), and the production readiness review template. It awaits migration `0010` and the backup secrets/R2 bucket in staging, a signed migration rehearsal, an isolated restore rehearsal within the four-hour RTO, security review sign-off, a go/no-go decision, and Sprint Review before the epic is marked done.
