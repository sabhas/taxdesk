Not in this release

  • No public sign-up, no social or Microsoft sign-in for staff, no email delivery of any kind.
  • No password-reset email: administrators issue reset links.
  • No list of active sessions, and no custom roles.
  • One currency (PKR). One firm per deployment.
  • No client portal: clients never sign in.
  • Client groups are one level deep, with no relationship type on the link. There is no group filter on the dashboard or reports, and no parent client column in the CSV import templates. A combined group invoice is paid as a whole; payments are not split between members.
  • No way to view a full CNIC/NTN on screen.
  • No OCR, search inside documents, document editing, or malware scanning.
  • No document storage other than OneDrive Personal.
  • Files read directly in the shared OneDrive folder are outside TaxDesk: anyone with the share sees every client's documents, whatever their role, and those reads are not in the activity history. Only opens through TaxDesk are checked and recorded.
  • No backup or restore screens: these are operator command-line tools.
  • Workflows are per firm. There is no library of shared templates beyond the starter.

  • The TD-704 PRD mentions a manager making import decisions, but only administrators have imports.manage. This guide follows the code.

  • The production Hyperdrive ID is still a placeholder. Production does not exist yet.
  • Status notes that ci:secrets flagged two synthetic values in an Epic 4 test file during Epic 5. Check that pnpm verify is green before a demonstration.

The one rule that overrides everything

No real client data before the gate

No real client data in any environment until the restore rehearsal (TD-708), the security review (TD-709), and the go/no-go decision (TD-710) have passed. Even after that, real data only ever goes into production.
