Local development setup

Run the full app on your own machine with a local PostgreSQL database and synthetic data. This is also the quickest training environment for staff.

1. Prerequisites

Tool Version Notes
Node.js 22 or newer Required by engines in package.json
pnpm 10 (pinned to pnpm@10.33.0) Run corepack enable and the pinned version is picked up automatically
PostgreSQL 17 recommended A local server, for example brew install postgresql@17 on macOS. Client tools (createdb, psql) are needed too.
OpenSSL any Used to generate local encryption keys
just optional Shortcuts such as just verify and just doctor (brew install just)
Authenticator app any TOTP app For example Google Authenticator, Microsoft Authenticator, 1Password, or Authy. MFA is mandatory, even locally.

2. Install dependencies

git clone <repository-url> taxdesk
cd taxdesk
corepack enable
pnpm install --frozen-lockfile
Moving between machines

If node_modules was installed on a different operating system or CPU (for example a shared drive), run pnpm install --force or just reinstall-force. Never delete pnpm-lock.yaml to fix a routine install problem.

3. Create the local database

The development Worker connects to postgres://taxdesk:taxdesk@localhost:5432/taxdesk_development by default. The easiest path is to create exactly that role and database: 

# macOS with Homebrew
brew services start postgresql@17

# Create the local role (password: taxdesk) and database
createuser --pwprompt taxdesk
createdb --owner taxdesk taxdesk_development

Any PostgreSQL works, including Docker or a managed development database. If you use different credentials, set them in the next step.

TLS only applies outside development

In the development environment the Worker connects without TLS, so a plain local Postgres works. Staging and production always require TLS.

4. Database connection files

Two different tools need the connection string:

  • The command-line tools (db:migrate, auth:*, ops:*) read DATABASE_URL.
  • The local API Worker reads its Hyperdrive binding. The binding defaults to the URL above and can be overridden with CLOUDFLARE_HYPERDRIVE_LOCAL_CONNECTION_STRING_HYPERDRIVE. 
cp .env.example .env

Then uncomment and edit the values in .env:

DATABASE_URL=postgres://taxdesk:taxdesk@localhost:5432/taxdesk_development?sslmode=disable
# Only needed if you are not using the default local database:
# CLOUDFLARE_HYPERDRIVE_LOCAL_CONNECTION_STRING_HYPERDRIVE=postgres://<user>:<password>@<host>:5432/<db>

.env and .env.local are git-ignored, and .env.local wins over .env. A value in your shell, or --database-url, wins over both. Use sslmode=disable only for a local database.

5. Apply the database migrations

pnpm db:migrate:verify    # checks migration files against the checksum manifest
pnpm db:migrate           # applies 0001–0010 in order
pnpm db:migrate:status    # every migration should show as applied

The migrations also seed the five built-in roles and their permissions. Migrations are forward-only: never edit one that has been applied anywhere. See docs/technical/migrations.md.

6. Local Worker secrets

Without these keys, the related features return 503 instead of running unprotected. Create packages/api/.dev.vars (git-ignored) from the example: 

cp packages/api/.dev.vars.example packages/api/.dev.vars

# Generate a separate key for each line below (run the command once per key)
openssl rand -base64 32 | tr '+/' '-_' | tr -d '='

Add these lines to packages/api/.dev.vars:

MFA_ENCRYPTION_KEY=<generated key 1>
CLIENT_DATA_ENCRYPTION_KEY=<generated key 2>
CLIENT_IDENTIFIER_INDEX_KEY=<generated key 3>
STORAGE_TOKEN_ENCRYPTION_KEY=<generated key 4>

# Cloudflare Turnstile public test keys (always pass). Only needed once a login is throttled.
TURNSTILE_SITE_KEY=1x00000000000000000000AA
TURNSTILE_SECRET_KEY=1x0000000000000000000000000000000AA

# Optional: a development Microsoft app registration, to try document uploads locally
# ONEDRIVE_CLIENT_ID=<application (client) id>
Missing value What stops working locally
MFA_ENCRYPTION_KEY MFA enrolment, so nobody can get past first sign-in
Client keys Creating clients, editing identifiers, CNIC/NTN search, client import
STORAGE_TOKEN_ENCRYPTION_KEY, ONEDRIVE_CLIENT_ID Document storage. The storage page reports "not configured". Uploads and invoice PDFs cannot be stored, but invoices themselves still work.
Turnstile keys After 5 failed sign-ins for one account (or 15 from one network) within 15 minutes, sign-in returns "Sign-in verification is not configured"

To try documents locally, follow OneDrive document storage with the redirect URI http://localhost:5173/settings/storage/callback. Keep the keys in .dev.vars stable: changing MFA_ENCRYPTION_KEY breaks everyone's MFA, and changing the client keys makes existing identifiers unreadable.

7. Create the firm and the first administrator

pnpm auth:bootstrap

It asks for the firm name, the administrator's username, display name, and password (twice, with at least 12 characters). It creates the firm settings (timezone Asia/Karachi by default) and writes a firm.bootstrapped audit event. It refuses to run a second time. For a throwaway database you can use flags: 

pnpm auth:bootstrap --non-interactive \
  --firm-name "Training Firm" --username admin --display-name "Training Admin" \
  --password "<a generated test password>"
Passwords on the command line end up in shell history

Use the interactive prompts for any database that matters.

8. Start the API and the web app

Use two terminals:

# Terminal 1: API Worker on http://localhost:8787
pnpm dev:api

# Terminal 2: web app on http://localhost:5173 (forwards /api and /health to 8787)
pnpm dev:web

Check the API is up:

curl -s http://localhost:8787/health
# {"environment":"development","releaseVersion":"0.0.0","requestId":"…"}

9. First sign-in

  1. Open http://localhost:5173.
  2. On Sign in to TaxDesk, enter the username and password from step 7.
  3. You are taken to Set up multi-factor authentication. Scan the QR code, enter the six-digit code, and select Enable MFA.
  4. Save the ten recovery codes, then select I have saved these codes.
  5. Continue with Build a training environment to add staff accounts and synthetic data.

10. Quality checks and tests

Command What it does
pnpm verify The full CI gate: typecheck, lint, format check, tests, migration verify, secret scan, workflow policy, config posture, self-test, build
pnpm typecheck · pnpm lint · pnpm test · pnpm build Run one gate across every package
pnpm format / pnpm format:check Rewrite or check Prettier formatting
pnpm ci:secrets Scan tracked files for secrets and forbidden files (.env, .dev.vars, .wrangler/)

Run one test file, or one named test, in a single package:

pnpm --filter @taxdesk/api test -- src/routes/auth.test.ts
pnpm --filter @taxdesk/api test -- src/routes/auth.test.ts -t "<test name>"

The PostgreSQL integration suites are skipped unless you point them at a disposable database whose name ends in _test: 

createdb --owner taxdesk taxdesk_migrations_test
createdb --owner taxdesk taxdesk_api_test

TAXDESK_MIGRATIONS_TEST_DATABASE_URL=postgres://taxdesk:taxdesk@localhost:5432/taxdesk_migrations_test?sslmode=disable \
  pnpm test:migrations

TAXDESK_API_TEST_DATABASE_URL=postgres://taxdesk:taxdesk@localhost:5432/taxdesk_api_test?sslmode=disable \
  pnpm test:api-db

11. Reset to a clean database

To start training again from nothing, drop and recreate the local database, then repeat steps 5 and 7. Never do this against staging or production. 

dropdb taxdesk_development
createdb --owner taxdesk taxdesk_development
pnpm db:migrate
pnpm auth:bootstrap

Faster alternative: take pg_dump of a prepared training database once, and restore it before each class.
