CI and delivery

How a change gets from a pull request to staging, and the gates that stop a bad change on the way. Full detail: docs/technical/ci.md.

The four workflows

Workflow Runs Does
ci.yml Pull requests, pushes to main, manual Jobs Quality gates (pnpm verify), Clean database migrations (migrate a brand-new Postgres and run the integration suite), and Secret history scan (gitleaks over the full history)
deploy-staging.yml After a successful CI push run on main, or a manual run with a full 40-character SHA The 12-step staging delivery below
platform-posture.yml Daily at 03:17 UTC Re-checks backup and point-in-time-recovery evidence and the latest export. Opens Platform posture check failed on failure.
backup-export.yml Daily at 21:41 UTC Encrypted pg_dump to R2 and manifest verification. Opens Independent backup export failed on failure.

Branch protection

Protect main and require Quality gates, Clean database migrations, and Secret history scan, with no bypass. Pull-request workflows never enter a GitHub environment or read secrets.*. pnpm ci:workflows enforces this, so editing a file in .github/workflows/ can fail CI.

Staging delivery, step by step

  1. Check the commit is a full 40-character SHA.
  2. Check out exactly that commit.
  3. Install from the lockfile.
  4. pnpm ci:config-posture: the staging Hyperdrive binding is real and the DB client requires TLS.
  5. pnpm db:migrate:verify
  6. pnpm db:migrate with STAGING_DATABASE_URL
  7. pnpm db:migrate:status --check
  8. pnpm ci:db-posture: TLS session, least-privilege role
  9. pnpm ci:backup-check: validates PLATFORM_POSTURE_EVIDENCE_JSON
  10. pnpm deploy:api:staging with RELEASE_VERSION set to the SHA
  11. pnpm deploy:web:staging
  12. pnpm ci:staging-smoke against STAGING_WEB_URL, expecting the deployed release version

When something fails

Failure What to do
A CI gate Fix it in the pull request. Never merge around or bypass a required check.
Staging deploy The previous Worker and Pages versions stay live. Re-run the workflow with the last good SHA, or fix forward.
Migration Its transaction rolls back and no ledger row is written. Add a compensating migration.
Migration manifest check An applied migration file was edited. Revert the edit. For a new file, run pnpm db:migrate:manifest.
Posture gate Do not deploy. Restore the control, update the evidence secret, and re-run.
Smoke test after deploy Treat the release as failed. Look up the request ID in wrangler tail, and redeploy the last good SHA if needed.

Running the gates locally

pnpm verify               # everything the Quality gates job runs
pnpm ci:selftest          # proves the gates reject deliberately bad input
pnpm ci:workflows         # workflow security policy
pnpm ci:config-posture    # staging config and TLS checks
