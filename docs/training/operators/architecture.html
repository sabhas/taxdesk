How TaxDesk fits together

Read this before setting up any environment. It explains the moving parts, so the setup steps on the next pages make sense.

One deployment serves one firm

Each firm gets its own TaxDesk stack: its own database, Worker, web project, secrets, and OneDrive connection. Records have no "organisation" field, and nothing is shared between firms or between environments.

Rules that shape everything else

  • The server decides who can do what. The web app hides buttons a role cannot use, but every API call checks permissions again.
  • Edits are version-checked. Editable records carry a version (ETag). Saving an out-of-date copy is rejected with 412 and the app shows a conflict screen. It never silently overwrites someone else's change.
  • Money commands are idempotent. Finalizing, payments, reversals, upload completion, and import commits carry an idempotency key, so a retry never charges twice.
  • History is append-only. Audit events, case-status history, finalized invoices, payments, and reversals are never edited or deleted.
  • Sensitive values are protected. CNIC and NTN numbers are encrypted and always shown masked. Tokens and MFA secrets are encrypted with keys that exist only as deployment secrets.
  • Firm time is used for dates. Timestamps are stored in UTC and shown in the firm's timezone (Asia/Karachi by default). Money is stored in whole paisa, and PKR is the only currency.
