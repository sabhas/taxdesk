Build a training environment

Every class and every UAT run starts from the same known setup: one account per role, a published workflow, a service, and a few hundred synthetic clients. This takes about 45 minutes the first time.

Synthetic data only

Use local or staging only. Never type a real client's name, CNIC, NTN, phone number, or document into a training environment, and never take screenshots of real data for training material.

2. Create one account per role

Sign in as the bootstrapped administrator, go to Users, and invite these accounts. The tests rely on two consultants, so preparer and reviewer can be different people.

For each account:

  1. Copy the one-time link and open it in a private browser window (or a separate browser profile).
  2. Set the password (store the training passwords in a shared training vault entry).
  3. Enrol MFA. One authenticator app can hold all seven training accounts. Label each one clearly, for example "TaxDesk training · t.billing".
  4. Save the recovery codes in the vault too. Some tests use them.
Testing several roles at once

Sessions use cookies, so one browser profile holds one user. Use separate browser profiles (or different browsers) to keep, say, the consultant and reviewer signed in side by side.

3. Firm setup (as admin)

  1. Firm settings: check the timezone is Asia/Karachi and keep the prefixes INV/RCP.
  2. Document storage: connect OneDrive (staging, or local with a development app).
  3. Workflows: New template named "Annual return", keep the starter content, Save draft, Publish version 1.
  4. Services: New service named exactly Income tax return (the sample generator uses this name), fee 25,000, deadline 30 days, duplicate policy Warn, default workflow "Annual return". Add a second service, "Sales tax registration", with policy Block for the duplicate-block tests.

4. Generate and import synthetic data

pnpm ops:sample-import --out training-data --clients 200 --seed 7 --with-exceptions
ls training-data
# cases-v1.csv  clients-v1.csv  opening_balances-v1.csv  source-totals.json
  • Same seed, same files, every time. Names come from a fixed word list, CNICs use the impossible 00000 region, and emails use example.test.
  • --with-exceptions adds rows that must be caught: a bad email, an in-file duplicate, and a possible duplicate. Good for training the review step.
  • Defaults: service "Income tax return", tax year 2026, as-of date 2026-06-30.
  • Keep training-data/ out of git. Treat it as disposable.

Then import as admin in order (clients, cases, opening balances), following Data import. Compare the totals with source-totals.json.

5. Make the data useful for each role

Imported clients and cases have no manager or consultant, so a consultant sees nothing yet. As t.manager:

  1. Set the assigned manager of 5 clients to t.consultant, and of 2 others to t.reviewer.
  2. Assign 5 open cases to t.consultant, with t.reviewer as reviewer.
  3. Leave a few cases unassigned (for the Unassigned queue), and set one due date in the past (Overdue) and one within 7 days (Due soon).
  4. Build two client groups (the CSV import cannot link clients, so do this by hand). Pick a business client as group head A and, for three other clients, Edit → Parent client = A → Save changes. Make A and two of those members ones that t.consultant manages, and leave the third member managed by someone else (so the consultant must not see or count it). Repeat with a second head E and one member.
  5. For group billing, as t.billing finalize an invoice for A and one for a member of A, record a part payment on one, and leave one draft. See the TD-207 scenarios.

6. Synthetic documents

Make a handful of harmless files: a one-page PDF saying "SAMPLE CNIC COPY – TRAINING", a PNG, a small XLSX, and one large file (over 10 MiB) to watch chunked upload, pause, and resume. Also keep a .exe or .zip to check that unsupported types are refused.

7. Snapshot it

Locally, save the prepared database so every class starts identical:

pg_dump -Fc -d taxdesk_development -f training-baseline.dump
# later, to reset:
dropdb taxdesk_development && createdb --owner taxdesk taxdesk_development
pg_restore --no-owner -d taxdesk_development training-baseline.dump

Restoring the database does not restore OneDrive files. Run reconciliation, or simply upload the sample files again.
