TaxDesk training guide

TaxDesk is a private practice-management app for one tax firm: clients, tax cases, documents, invoices and payments, reports, and data migration. This guide teaches people to set it up, use it, and test it.

Before you start: this release is not live yet

Epics 0–7 are built and pass every local check. Each epic still needs a staging demonstration and Sprint Review sign-off. Real client data may not be loaded anywhere until the restore rehearsal (TD-708), the security review (TD-709), and the go/no-go decision (TD-710) have passed. See Release status and limits.

Pick your track

Track A · Operators

Set up and run TaxDesk

Local development, staging, and production; secrets; OneDrive; CI; backups, restores, and lockout recovery.

Track B · Firm staff

Use TaxDesk day to day

Signing in with MFA, then clients, cases, documents, billing, reports, and administration, explained role by role.

Track C · Testers

Test every user story

Build a training environment with synthetic data, walk through a full day at the firm, then work through the UAT catalogue and record results.

Suggested training plan

Session Who Read Practise
1. Platform (half day) Operator Track A, all pages Run TaxDesk locally, bootstrap an administrator, deploy staging
2. Everyone (1 hour) All staff Getting started, Roles, Security Activate an account, enrol MFA, store recovery codes, sign out
3. Casework (2 hours) Manager Consultant Clients, Services and workflows, Cases, Documents Steps 1–6 of the end-to-end walkthrough
4. Billing (1 hour) Billing Manager Invoices and payments, Dashboard and reports Steps 7–9 of the walkthrough
5. Administration (2 hours) Administrator Administration, Data import, Backup and lockouts Invite users, connect storage, run an import dry run, review audit history
6. UAT (several days) Testers, Product Owner UAT scenario catalogue Run every scenario per role and export the results CSV for sign-off

Conventions in this guide

  • Button text is shown exactly as it appears in the app. Navigation items are written like Clients → New client.
  • Role badges show who can do something: Administrator Manager Consultant Billing Read-only Operator. An operator is someone with deployment access (Cloudflare, database, GitHub), not an app role.
  • Commands run from the repository root unless stated otherwise. Values in <angle brackets> are placeholders you replace.
  • Story IDs (for example TD-306) match the product requirement documents in docs/product/prd/.
  • Press / to search. The ◐ button switches light and dark mode, and ⎙ prints the current page.

Where this guide comes from

Labels, routes, and limits come from the source code (packages/web/src, packages/shared/src). Procedures come from the runbooks in docs/guides/ and docs/technical/. If the app and this guide disagree, the app is right; please update the guide.
