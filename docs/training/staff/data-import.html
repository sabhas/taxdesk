Data import

Bring existing clients, open cases, and opening balances in from spreadsheets. Nothing is written until a dry run is clean and you commit it. A dropped connection never imports anything twice. Full reference: docs/guides/data-import.md.

Download templates from the Templates list on Data import. Before importing cases, create the services they reference and publish their default workflows.

File rules

  • UTF-8 CSV. The header must contain exactly the template's columns, in any order.
  • At most 2 MiB, 5,000 rows, and 4,000 characters per cell. Split bigger sources.
  • Every row needs an external_ref: the record's ID in the old system, unique within the file. Re-importing the same reference updates the client, or skips the case or balance, instead of duplicating it.
  • Row 1 is the header, so row 2 is the first data row, just like in a spreadsheet.
  • CNIC is 13 digits for individuals and empty for businesses. NTN is required for businesses. Phones are 7–15 digits. Dates are YYYY-MM-DD. Amounts are PKR above zero with at most two decimals.

Dry run, review, commit

  1. Dry run. Under New dry run, choose the Template and CSV file, then Run dry run. TaxDesk records the file's name, size, row count, and checksum (not the file itself) and shows the plan: Create, Update, Skip, Possible duplicates, Errors. Nothing is written yet.
  2. Fix errors. Each error names the row, the column, and a fixed reason, and never repeats the cell's value. Correct the source and run a new dry run (Discard the old batch first). A batch with errors can never be committed.
  3. Decide possible duplicates. For rows that look like an existing client (same name, email, or phone, but not the same CNIC/NTN), select Decide. Choose Skip this row (it is the same client) or Create a new client anyway, write a Reason (at least 10 characters), and Save decision.
  4. Revalidate if records changed since the dry run, for example after you added a missing service.
  5. Commit. Choose the same file again and select Commit import. Rows are written in batches of 100, and each record gets its normal audit event plus the batch code and row number.
  6. Interrupted? The batch shows Committing. Choose the same file and select Resume commit. It continues from the next unwritten row, and no row is ever written twice.

Batch statuses

Ready to commit · Needs attention · Committing · Committed · Discarded

Check the result

  • Each batch shows source rows against created, updated, skipped, failed, and pending rows. For opening balances it also compares money totals. Reconciled means every row is accounted for.
  • Exceptions CSV lists every error, skip, duplicate, and decision. Lineage CSV (after commit) maps every row to the record it created or updated. Neither contains cell values.
  • Migration reconciliation on the Data import page totals what was imported and shows a random sample of rows to compare against the source.
